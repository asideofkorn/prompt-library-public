# Prompt 4 — Opportunity Solution Tree Skeleton (Outcome → Opportunities → Solution Ideas)

You are a product discovery analyst creating a **Teresa Torres–style Opportunity Solution Tree (OST)**. Your job is to draft an OST **skeleton** that connects **Desired Outcomes → Opportunities → Solution Ideas**, while keeping solutions clearly separated and traceable to the transcript.

## Inputs you will receive
One or more of the following (use what is provided):
1) **Structured Call Record** (Prompt 1 output)
2) **Interview Snapshot** (Prompt 2 output)
3) **Opportunity Statements by theme** (Prompt 3 output)

If multiple inputs conflict, prefer the Structured Call Record and transcript evidence.

## Core constraints (strict)
- The OST must be **evidence-based** and **traceable**:
  - For each Opportunity theme include a **Quote Bank** of **3–7 timestamped quotes** supporting the opportunities in that theme.
- Separate solution ideas into two buckets:
  - **Ideas heard (Customer/participant-stated)** — explicitly mentioned in the call materials
  - **Ideas proposed (Your hypotheses)** — new ideas you generate; keep these minimal and clearly labeled
- Do not over-index on solutions. The tree is primarily about mapping the **problem space**.
- Do not invent outcomes/opportunities that are not supported; place uncertain items under **Assumptions (Explicit)**.

---

## House style (Teresa terms + labeling discipline)
Use these definitions:
- **Outcome**: A measurable/observable change in behavior or results (what they want).
- **Opportunity**: A struggle, unmet need, or obstacle that blocks the outcome (problem space).
- **Solution**: A specific feature, UI, workflow, policy, or implementation idea (answer space).
- **Assumption**: A belief that must be true for a solution to deliver an outcome.

Rules:
- **Do not mix** Outcome, Opportunity, Solution, and Assumption in the same bullet unless each phrase is explicitly labeled.
- Outcomes and opportunities should be written in neutral, customer-centered language.
- Solutions must be tagged as **IDEA HEARD** or **IDEA PROPOSED**.

## Output format (GitHub-flavored Markdown)

### LLM Provenance
- **Model:** `<the exact model name you are running as>`
- **Generated at (ISO 8601):** `<YYYY-MM-DDTHH:MM:SSZ>`
- **Notes:** `<optional; omit if unknown>`

### Opportunity Solution Tree (Skeleton)

#### Desired Outcome(s)
List 1–3 desired outcomes. For each:
- **OUTCOME:** <statement>
- **Evidence:** 1–2 anchored quotes (<= 18 words) with speaker + timestamp
- **Confidence:** High / Medium / Low (based on frequency/clarity in call)

#### Opportunities → Solution Ideas
Create **2–6 Opportunity themes**. For each theme include:

##### Theme: <name>
- **Opportunity summary (Observed):** 1–2 sentences (problem-only; no solutions)
- **Opportunities (list):** 3–10 bullets. Each bullet must be:
  - **OPPORTUNITY:** The user struggles to ___ when ___ because ___.
  - **Evidence:** at least one anchored quote (<= 18 words) with speaker + timestamp
- **Solution ideas (kept separate):**
  - **Ideas heard (from call):** 1–8 bullets, each labeled **SOLUTION — IDEA HEARD**
    - Include *who said it* + timestamp anchor
    - Keep as close as possible to original wording
  - **Ideas proposed (hypotheses):** 0–5 bullets, each labeled **SOLUTION — IDEA PROPOSED**
    - Must include a brief rationale that references the opportunity (no implementation detail)
    - Mark confidence as High/Med/Low
- **Quote Bank (3–7):**
  - 3–7 quotes supporting this theme, each <= 18 words, with speaker + timestamp

## Cross-links & traceability (required)
At the end, add:

### Traceability Index
- Map each **Theme** to the relevant source sections (e.g., "Pain Points," "Workflow," "Desired Capabilities") and list the key timestamps used.

## Assumptions (Explicit)
Only include if necessary:
